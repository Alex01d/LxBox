# Транспорт между узлами — обычный Tailscale, AWG2 и AWG3

| Поле | Значение |
|------|----------|
| Фича | [030-TAILSCALE](../FEATURE.ru.md) |
| Обещания | P25–P26 |
| Состояние | Engineering-реализация; приёмка на физическом устройстве впереди |

## Назначение и настройки

Доступ к сети Headscale и выбранный интернет-прокси в одном VPN-приложении.
Выбор обычного Tailscale/AWG2/AWG3, импорт/правка/экспорт профиля с версией,
необязательной меткой и типизированными параметрами транспорта. Auth key
необязателен: ссылка входа допускает ручное одобрение Headscale. Оба VPN-узла
должны поддерживать выбранный режим и совместимые параметры; обычные Headscale
и DERP не требуют AWG-форка.

Транспорт работает напрямую по UDP, через явный UDP-прокси либо через DERP в
явном TCP-прокси. Отказ выбранного внешнего прокси не разрешает прямой fallback.
Статус direct означает отсутствие DERP; внешний прокси всё ещё может быть.

## Входы, выходы и инварианты

- Профиль несёт параметры транспорта, но не личность устройства. В экспорте
  возможен общий ключ обфускации. Правка/reload сохраняют местную личность;
  импорт на другое устройство выдаёт ему собственную личность.
- Отсутствующая/неизвестная поддержка AWG отвергает весь кандидат и сохраняет
  last-good. Автоматического перехода на обычный WireGuard нет. Атомарный
  бэкап требует marker 3; обычный экспорт остаётся marker 2.
- Настроенный/применённый режим и безопасная ошибка отделены от доступности
  пира. Применение профиля/control handshake не доказывают data plane.
- Обычные и AWG-узлы могут иметь общий control server, но не взаимодействуют
  прозрачно. Peer relay и встроенный SSH server с AWG пока вне интеграции.

## Проверка и границы

Свидетели задачи 700: профиль/schema/round-trip, capability, backup и optional
status tests. Wi-Fi/mobile, фон/перезапуск UI, consent revoke, direct/DERP,
отрицательные/leak сценарии и обычные режимы проверяются на выделенном
устройстве. Собранный APK не означает device acceptance или production rollout.
